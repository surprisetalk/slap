# claude.md

Guidance for working in this repo. The language itself is documented in readme.md.

## Build and run

```bash
make slap                        # terminal interpreter (C99, -O3 -flto, -lm)
make slap-sdl                    # SDL2 build (-DSLAP_SDL)
make slap-wasm FILE=prog.slap    # Emscripten build of one program
./slap [--check] [--headless] [--profile] [args...] < file.slap
```

With a TTY on stdin and no `--check`, `./slap` is a shell (`shell`): each line is checked after the lines it accepted (the checker runs again over the whole history; `infer_program` resets its state on entry and skips the end-of-program copy rule), then the line alone runs in the global frame. A failed line is discarded: `die` longjmps back, the stack returns from a deep copy taken before the line, and the global frame is trimmed to its old count, which undoes the line because names are never rebound. During a line `tcp-close` only notes its socket (`shell_sock`); a kept line closes those, and a discarded one closes the sockets it opened instead. A discarded line stays in the history as an empty line, so line numbers match what was typed. `--check` type-checks and stops. A plain run type-checks first too, so `--check` before a run is redundant. `--headless` gives `show` no window: it sends `'resize` 640 480 once, then runs the tick handlers and the render body each frame until a handler fails. `--profile` prints folded stacks (`word;word nanoseconds`) to stderr at exit.
A plain run refuses a program that names a word this build lacks (SDL words in `./slap`, `tcp-*` in wasm) before anything runs, even when the word sits in a branch that never runs; `--check` accepts it.

## Tests

```bash
make test        # tests/suite.py: every check in parallel, a few seconds; builds slap-sdl where SDL2 is installed
make test-slow   # the Euler problems in SLOW_EULER (tests/suite.py)
make status      # every likely failure mode, scored; 1.0 is the minimum pass
```

- New behaviour gets an assertion in `tests/expect.slap`. expect.slap needs `examples/lib/strings.slap` and `parse.slap` prepended and runs as `./slap hello world <scratch-file>`; suite.py does both.
- A new error gets a case in `tests/errors.slap`: one or more `-- EXPECT: <text>` lines, optional `-- EXPECT-LINE:`/`-- EXPECT-COL:`, then code up to the next EXPECT. A case fails on exit 0, on a signal, or on a timeout.
- A bug gets a failing test first. Check it fails against the old binary; a test that cannot fail is not a regression test.
- Breaker and fuzz rounds run an ASan/UBSan build: `cc -std=c99 -g -O1 -fsanitize=address,undefined -D_POSIX_C_SOURCE=200809L -o slap-asan slap.c -lm`. The runtime trusts the checker, so a checker hole shows up as memory damage or a wrong answer, not as a message. Never link SDL into an ASan build: on macOS, sdl2-compat cannot load SDL3 under ASan, and each run opens two dialogs on the user's screen. Test SDL words with the plain `make slap-sdl` binary and `--headless`.
- macOS ignores `ulimit -v`, so a program that allocates without end fills the disk with swap and takes the machine down. Never run one: no `read` of `/dev/zero`, `/dev/urandom` or a FIFO, and no binary older than a limit on input past that limit. A test of a limit reads a bounded input, such as a file one byte past it. Run unbounded experiments on pc (Linux) under `ulimit -v`.
- `tests/scale.slap` holds library inputs too large to run on every load (past the interpreter's recursion limit); suite.py runs it once.
- `make test-uxn-refs` compares `examples/uxn.slap` pixel for pixel with mkeeter/raven's reference renders (network on first run, cached in `tests/.uxn-refs/`). Run it after touching uxn.slap's Screen path. The 60-frame count matches raven's harness and is load-bearing. `make test-uxn-sweep` checks each ROM's render moves with the frame count as declared. bunnymark is not a benchmark: its population never grows.

## Architecture

One file, `slap.c`: lex → type-check → eval.

- **Lexer** turns source into tokens. Each bracket token records the offset to its partner (`span`), so nothing scans for matches. String literals are UTF-8 bytes.
- **Checker** (`infer_program`) runs over the prelude and the program before anything executes. A type is a term in one pool (`Ty`); a string literal's and `str`'s `K_LIST` carries `sym` = 1, which `ty_unify` ignores and messages print as `str` (any other int list prints `int list`); `ty_unify` binds variables with union-find, and a structural link waits until the whole chain unifies (`ty_links`). Kinds: values (`K_INT` to `K_TAG`), stacks (`K_SVAR`, `K_SNIL`, `K_SCONS`), record rows (`K_RVAR`, `K_RNIL`, `K_REXT`, with fields `K_PRE`/`K_ABS`), labels (`K_LSYM`, a record key) and tag sets (`K_TVAR`, `K_TNIL`, `K_TEXT`). A body is `K_FN`, from the stack it takes to the stack it leaves. `TYPES` holds the primitives' types (`( ins -> outs )`; `--` would start a comment); the prelude's words are inferred like the program's. Levels decide generalization: a word defined from a body written in place is generic, a value is not, so a body bound with `let` runs at one stack depth. A signature is rigid (`ty_rigid`), and a variable that would escape its scope is an error (`ty_occurs` returns 2). A body type in a slot runs on the word's own rest (`ty_slot_rest`). Each recursive call gets a fresh stack rest, made at its word's level (`ty_rec_owner`). Every tag but `'ok`/`'no` has one payload type program-wide (`ty_tag_payload`); `'ok`/`'no` build `K_RES`. `case` takes only its clauses, and `ty_case` proves coverage at the case: without a last `'_` clause the value unifies with a closed tag set (`K_TNIL` tail) of exactly the clause tags, which refuses a tag with no clause and a clause for a tag the value never carries. With `'_` the value may carry any tags, since a clause's payload type is its tag's everywhere; on a closed set, a clause for a tag the set lacks, or a `'_` after a clause for every tag, is refused as dead. A type variable carries one bit, `copy` (`P_COPY`), which is ownership. `plus sub mul div lt sort` take ints and `fplus fsub fmul fdiv flt` take floats; each f-word runs its int word's primitive, since the runtime tells int from float by tag. Ownership: `TYPES` asks for it where a primitive drops or duplicates a value or a container holds one, and `let`, literals, `show` and the program's last stack ask for it too. No word ends a program early: a word that holds a box aside while it runs a caller's body cannot see an exit inside that body, so the box would leak. `show` exits when its window closes, so it asks copy of the whole stack. The stack below the bodies of `each`, `fold`, `edit`, `mutate` and `lend` is sealed (`..!r` in `TYPES`). A pending forward declaration forbids running code in its scope (`ty_runs`), since that code may call it. Code in a literal sees only top-level names (`ty_lit_depth`).
- **Records** are rows of present or absent fields: `into` takes `{'k 'p field | 'r}` and leaves `{'k 't | 'r}`, since the runtime replaces a key it finds; `at` and `edit` need `'k` present. `at`, `into`, `edit` and `nth` read the symbol written right before them (forms in `ty_range`, not `TYPES` entries). Every symbol has the one type `K_SYM`; a symbol literal's `K_SYM` keeps its name for `{...}` keys and `on`'s event, and two different names that meet clear it. `at` and `edit` never fail at runtime, and the runtime does not look for a missing key.
- **Evaluator**: `build_tuple` turns tokens into a tuple body; `eval_body` runs it. A word resolves at build time to its primitive (`prim_fns`, indexed by symbol) or, for `X must`, to the fused variant (`prim_must_fns`). Other words look up a frame binding when they run: a binding is a word (`Binding.word`) when a body was written right before its `'name let`, and a lookup runs a word and pushes any other value. Under `--profile` primitives stay unresolved, so every word reaches `prof_dispatch`. `[...]` and `{...}` literals are evaluated by `build_tuple`, once, when the program is read; `{...}` is always a record. `{clauses} case`, `(body) pthen`, `(body) dip`, `(then) (else) if` and `(pred) (body) while` written in place run from the body itself instead of copying their bodies to the stack and the aux stack; `make status` times a 600 KB feed, which depends on it. These run in the running frame, never in the frame a literal's header names: that is the frame it was built in.
- **Frames** are lexical. Each run of a body that binds names (`VF_BINDS` on its tuple header, set by `build_tuple`) gets a frame from a pool whose parent is the frame the body was made in; top-level code binds straight into the global frame. A frame counts what keeps it (`refs`): its run, the tuples that close over it (`deep_copy_values`/`deep_free_values` count them, and a lookup's copy counts again) and its child frames. Tuples in its own bindings do not count, so a word's local words do not keep it. At zero it waits on a list, and one loop releases the bindings of every waiting frame, so a chain of closures frees without C recursion. Then the frame goes back to the pool. A run's frame that only the run holds (refs 1, no hash table) skips the waiting list: `frame_end_run` releases its bindings and pools it. A primitive's `POP_BODY` bodies, and `case`'s clause list, lose their reference when it returns (`staged`); one that holds a dict is freed whole. `case` clauses run in the frame that runs `case`. Refcounts free no cycle, so the checker forbids the binding that would close one (`ty_taint`, `ty_no_body`, `P_NOFN`): once a body that makes a frame has pushed a body as a value (not an in-place if, while, dip, pthen or case body), a `let` in it may not bind a value that holds a body. A body bound before that point, or as a word, is fine; a generic word's variable bound there takes `P_NOFN`, so a caller that passes a body is refused. The top level's frame is never freed and is exempt. Each binding owns a heap block of its values. The hot lookup and bind paths are forced inline.

## Invariants

- A compound is a flat run of `Value`s on the operand stack with its header last. Primitives move runs in place (`memmove`, `swap_blocks`, `replace_run`). Anything that must step aside while code runs goes on the aux stack (`aux_take`). No C buffer may be sized by data: it overflows the C stack with no message.
- The aux stack never moves, so bodies execute from it; `eval_body` releases what a primitive staged when the primitive returns.
- `dispatch_word` pins the block a word executes from; `frame_bind` never writes into a pinned block.
- Deep-copy (never `VCPY`) when a value is duplicated and its source survives (`dup`, `peek`, `nth`, `of`, `lend`): boxes and dicts are heap objects with one owner.
- A binding that holds a dict owns it (`Binding.heap`): a lookup deep-copies it, and rebinding, trimming or restoring the binding frees it; a closure's child frame takes it over. A `[...]` or `{...}` literal is built once, so pushing one that holds a dict (`VF_DICT` on its header, set by `build_tuple`) deep-copies it. The checker refuses a binding of a box or socket. Tagging a linear value keeps it linear.
- parse.slap's combinators scan with an index and cut once; recursing per character exhausts the C stack.
- A lookup of a bound list deep-copies it, and `drop-n`/`take-n` copy what they keep, so a library loop that does either per element is O(n²). Keep a growing list on the stack, and cut once after a search.
- Removing a limit exposes whatever it was hiding. Audit every consumer of the newly unbounded value first.
- Integer `plus`/`sub`/`mul` wrap at 64 bits. Division by zero, `INT64_MIN -1 div`, and shift counts outside 0-63 are errors.
- Every runtime failure exits nonzero with a message naming what was expected and what arrived. Never clamp, default, or skip to keep running.
- The runtime trusts the checker: it never checks what the checker proves (types, stack depth, record keys, case coverage, a body's output count). A check that only catches a checker bug does not belong in a primitive.
- A library returns `'no` for input it cannot read. `must` stays only after a check of the same condition, or on a structure the program built.
- Reading element `i` of a list whose elements span several slots walks the list, so a loop of `nth`/`get` over records or tagged values is O(n²). Use `each`, `filter`, `fold` or `index-of`.

## Fallible operations

These return `value ok` on success and `none` (or `payload no`) on failure:

| Operation | Success | Failure |
|---|---|---|
| `pop` | list, then `element ok` | list, then `none` when empty |
| `get` / `peek` / `nth` | `element ok` | `none` out of bounds (`get` consumes the list, `peek` leaves it, `nth` reads the bound name written right before it, as in `1 'xs nth`) |
| `set` | `list ok` | `none` out of bounds |
| `index-of` / `str-find` | `index ok` | `none` |
| `of` (dict lookup) | `value ok` | `key no` |
| `read` / `write` / `ls` | `bytes ok` / `1 ok` / `entries ok` | `"path: reason" no`, the reason from `strerror` |
| `tcp-connect` / `tcp-send` / `tcp-recv` / `tcp-listen` / `tcp-accept` | `socket ok` / `1 ok` / `data ok` / `socket ok` / `client ok` | `message no` |

A connected socket times out: `tcp-recv` after 30 s with no data (`SO_RCVTIMEO`, set in `sock_setup`, so never on a listening socket); `tcp-send` 30 s after it starts (it sends without blocking and polls, since a blocking send restarts its timeout on any progress); `tcp-connect` after 10 s. `tcp-accept` blocks, and skips a client that resets before it is done (a failed accept, or on macOS a refused socket option); `tcp-listen` binds loopback. `write` replaces a regular file atomically (`write_atomic`: a `.slapXXXXXX` temp in its directory, fsync, rename; mode and group kept, a symlink followed, a file the user may not write refused). Where a replacement could not match the file (another owner, a hard link, a directory the user may not write, a refused fchmod or fchown) and for a device, FIFO or directory, it writes in place (`write_in_place`). slap ignores SIGXFSZ, so a size limit fails the write. A SIGKILL between mkstemp and rename leaves the temp. `read`, `write`, `ls` and `tcp-connect` give `'no` for a path or host with a NUL byte (`"path: contains a NUL byte"`). `at` and `edit` are not fallible: the checker proves the key, and `at must` is an error unless the field holds a result. `take-n`/`drop-n` clamp a count past the end; a negative count is an error. `must` unwraps `'ok` and dies on anything else. `fail` (`..a str -> ..b`) dies with its text at the nearest call outside the prelude, so any stack may follow it; use it where a branch needs a free stack. Bodies given to `each`, `fold`, `mutate` and `lend` must leave exactly one value; the checker proves it.
